# Трекер для двох: Оля і Марко

Облік витрат на [Beancount 3](https://beancount.github.io/) і [Fava](https://beancount.github.io/fava/), який Оля й Марко відкривають з телефона за паролем.
У репозиторії лише штучні виписки з домашнього завдання.

## Одна команда перевірки

```bash
uv run check.py
```

Команда заново імпортує обидві виписки, запускає `bean-check` для трьох обліків і друкує контрольні цифри. Очікуваний результат:

```
1. bean-check
   olya.beancount: без повідомлень
   marko.beancount: без повідомлень
   spilne.beancount: без повідомлень

2. Контрольні цифри: змінні витрати, зл
   Оля    08.2026:   2195.21  збігається
   Оля    09.2026:   2582.42  збігається
   Марко  08.2026:   1855.57  збігається
   Марко  09.2026:   2432.83  збігається

3. Хто кому винен за спільне (оренда, Kaufland, Auchan, світло, інтернет)
   08.2026: Оля заплатила 3200.00, Марко 888.17 → Марко винен Олі 1155.92
   ...
УСЕ ГАРАЗД
```

Потрібен лише [uv](https://docs.astral.sh/uv/): він сам поставить Python-залежності з `pyproject.toml`. Код виходу 0 означає, що все зійшлося.

## Що є в трекері

| Хто входить | Що бачить |
|---|---|
| `olya` | свій облік «Оля» і «Спільне» |
| `marko` | свій облік «Марко» і «Спільне» |

- **Звіт за місяць** (відкривається одразу після входу): витрати за категоріями, норма заощаджень, фіксовані й змінні витрати. Неповний місяць підписано датою, до якої є дані.
- **«Спільне»**: хто кому винен за місяць. Спільні витрати ділимо навпіл: оренда (платить Оля), Kaufland, Auchan, світло PGE та інтернет Orange Światłowód (платить Марко). Хто скільки вніс, записано як `Income:Заплатив:<імʼя>`, тож у «Доходи і витрати» внески й витрати видно додатними числами. Власних грошей у спільного обліку немає, тому меню там із трьох пунктів, а «Усі операції» показує всі спільні покупки.
- **Меню без бухгалтерії**: «Звіт за місяць», «Доходи і витрати» (дохід і витрати додатними числами), «Гроші на рахунках», «Усі операції» (виписка з сумою й залишком) і кнопка «Додати витрату». Технічні сторінки Fava сховано, англійські підписи перекладено (`ui/`).
- **Готівка з телефона**: кнопка «Додати витрату» (у Fava це «+»). Запис зберігається у `ledgers/<імʼя>-manual.beancount`, і імпорт його не затирає. Для готівки є рахунок `Assets:Готівка`.

## Як це влаштовано

```
data/                       штучні виписки (формати двох різних банків)
rules-olya.csv              правила категорій Олі: шаблон, рахунок, фіксована, спільна
rules-marko.csv             те саме для Марка
importer.py                 виписки + правила → ledgers/*-transactions.beancount
ledgers/olya.beancount      облік Олі (рахунки, початковий залишок, includes)
ledgers/marko.beancount     облік Марка
ledgers/spilne.beancount    спільні витрати обох, для «хто кому винен»
ledgers/queries.beancount   збережені запити (вкладка «Запит» у Fava)
ledgers/fava_report/        розширення Fava «Звіт за місяць»
app.py                      вхід за паролем перед Fava
ui/                         спрощений вигляд Fava: що сховати і як назвати
check.py                    одна команда перевірки
```

- Місяць визначаємо за датою завершення операції (Оля) і датою операції (Марко).
- Фіксовані витрати позначено тегом `#fixed`: в Олі оренда, ZTM, Netflix, Spotify, Claude.ai, Play; у Марка Orange, PGE, Zdrofit, YouTube Premium.
- Імпорт звіряє облік з банком: після кожного місяця є перевірка `balance` за колонкою залишку.

## Безпека

- Без входу трекер не показує жодних даних: кожна адреса, крім `/login`, без cookie переадресовує на вхід. Чужий облік повертає 403.
- Паролі й ключ підпису cookie беруться лише зі змінних середовища `SECRET_KEY`, `OLYA_PASSWORD`, `MARKO_PASSWORD`. Без них застосунок не запускається.
- Лише HTTPS: запит по HTTP переадресовується на HTTPS, cookie має прапорці `Secure`, `HttpOnly`, `SameSite=Lax`.
- Редактор файлів та імпорт у Fava вимкнено на сервері: змінювати можна лише витрати, додані кнопкою «+» (файл `*-manual.beancount`). Так облік не зламати випадково з телефона.
- Після 5 невдалих спроб входу з однієї адреси вхід блокується на хвилину.
- Двофакторний вхід не додавали: для двох людей зі штучними даними пароль плюс HTTPS достатні, а 2FA ускладнила б вхід Марку з телефона.

## Локальний запуск

```bash
SECRET_KEY=$(openssl rand -hex 32) OLYA_PASSWORD=пароль-олі MARKO_PASSWORD=пароль-марка ALLOW_HTTP=1 uv run app.py
```

Відкрити http://127.0.0.1:5050. `ALLOW_HTTP=1` лише для свого компʼютера, на сервері його не ставимо.

## Розгортання на PythonAnywhere (безкоштовно)

1. **Consoles → Bash**:
   ```bash
   git clone https://github.com/spoliukhovych/my-finance-duo.git
   python3.13 -m venv ~/venv
   ~/venv/bin/pip install -r my-finance-duo/requirements.txt
   cd my-finance-duo && ~/venv/bin/python check.py
   ```
2. **Web → Add a new web app → Manual configuration → Python 3.13.**
3. У розділі **Virtualenv** вказати `/home/<логін>/venv`.
4. Відкрити **WSGI configuration file** і замінити весь вміст на:
   ```python
   import os, sys
   os.environ["SECRET_KEY"] = "довгий-випадковий-рядок"
   os.environ["OLYA_PASSWORD"] = "пароль-олі"
   os.environ["MARKO_PASSWORD"] = "пароль-марка"
   sys.path.insert(0, "/home/<логін>/my-finance-duo")
   from app import application
   ```
   Цей файл лежить лише на сервері, тож паролі не потрапляють у репозиторій.
5. У розділі **Security** увімкнути **Force HTTPS**, натиснути **Reload**.
6. Безкоштовний вебзастосунок треба продовжувати кнопкою **Run until 3 months from today** на вкладці Web.

Оновлення після змін у репозиторії: `cd ~/my-finance-duo && git pull && ~/venv/bin/python check.py`, потім **Reload**.

## Що спростили під безкоштовний тариф

- Один вебзастосунок на двох: обидва входять на ту саму адресу, а розмежування робить `app.py`.
- Користувачі й паролі задано змінними середовища, без бази даних і реєстрації.
- Виписки завантажуються в `data/` вручну і імпортуються командою, без автозавантаження з банку.
